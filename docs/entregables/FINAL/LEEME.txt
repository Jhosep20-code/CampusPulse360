3. DEMOSTRACION SIN INTERNET (Docker, en la laptop)
------------------------------------------------------------------------
Requisitos: Windows con Docker Desktop abierto. Node 24 es opcional (ver 3.1-B).
Los comandos son para PowerShell, dentro de la carpeta donde se descomprimio el codigo
(la que contiene compose.yaml).

3.1  CON INTERNET, ANTES DE LA DEMOSTRACION (una sola vez por laptop)

  Paso 1. Generar las credenciales LOCALES (crea infra/local.env con valores aleatorios;
          no los muestra, no sobrescribe un archivo existente y no usa claves de produccion).

    A) Con Node 24:
       node infra/generar-env-local.mjs

    B) Sin Node, usando Docker:
       docker pull node:24-bookworm-slim
       docker run --rm -v "${PWD}\infra:/infra" node:24-bookworm-slim node /infra/generar-env-local.mjs

  Paso 2. Descargar las imagenes y construir con sus dependencias (varios minutos; necesita red):
       docker compose pull cron
       docker compose build

  Paso 3. Arrancar una vez y comprobar:
       docker compose up -d --no-build --pull never --wait
       docker compose ps
     Abrir http://localhost:8787 y http://localhost:8787/api/v1/system/health (debe decir ok).

  Paso 4. Crear el administrador local (sirve para lanzar escenarios):
       notepad infra\local.env
     - Abrir http://localhost:8787/acceso (usar "localhost", no 127.0.0.1).
     - En "Alta inicial": pegar el valor de BOOTSTRAP_TOKEN, escribir un nombre,
       elegir Administrador y pulsar "Registrar passkey" (confirmar con Windows Hello o PIN).
     - Cerrar el Bloc de notas sin guardar. No mostrar ni grabar ese archivo.
     El token sirve UNA sola vez. Esta passkey es solo de localhost: no es la de produccion.

  Paso 5. Detener sin borrar nada:
       docker compose stop

3.2  EL DIA DE LA DEMOSTRACION, SIN INTERNET

       docker compose up -d --no-build --pull never
       docker compose ps
     Abrir http://localhost:8787 e iniciar sesion en /acceso.
     Centro de mando > Demostracion > "Lanzar escenario". La incidencia aparece en 1 a 3 minutos.

  Al terminar:
       docker compose stop

3.3  QUE CAMBIA SIN INTERNET
  - No hay Workers AI: el diagnostico y el asistente usan el respaldo por reglas, rotulado "sin IA".
  - La AR en el telefono necesita la demo publica por HTTPS (internet o punto de acceso movil).
  - Las passkeys y los datos de produccion no existen en local.

3.4  SI ALGO FALLA
  - "Falta GATEWAY_KEYS": no se genero infra/local.env (paso 1).
  - Puerto 8787 ocupado: cerrar el programa que lo usa.
  - "No such image" o intento de descarga sin red: faltaron los pasos 2 y 3.
  - Perdiste la passkey local: "docker compose down -v" BORRA solo la base local de Docker
    y permite repetir el alta (paso 4). No afecta a produccion.
  - Ver registros: docker compose logs api --tail 50
